# Issueを実装する

## 手順

1. Issue の内容を確認し、必要に応じて利用者に質問する。
2. Issue 用のブランチを作る。ブランチ名は `<種別>/issue-<Issue番号>-<内容を表す短い英語>` の形式にする（例: `fix/issue-1-user-id-ownership`）。種別は変更内容に応じて `fix`（不具合修正）、`feature`（機能追加）などを使い分ける。
3. 受け入れ条件を満たす最小限の変更を行う。
4. 処理内容がすぐに理解できるようなコメントを細かく記載する。
5. 必要に応じて実装の意図を説明するコメントを記載する。
6. 変更内容、テスト結果、残る課題を報告する。

## 停止条件

- 仕様が曖昧で結果が変わる。
- 本番データや秘密情報に触れる必要がある。
- 破壊的な変更が必要になる。
- 想定より変更範囲が大きくなる。
- テスト、Lint、ビルドが失敗する。

このSkillではpushとPR作成を行わない。
