# Draft PRを作成する

## 手順

1. 対象Issue、現在のブランチ、差分を確認する。
2. 無関係な変更がなく、必要な検証が成功していることを確認する。
3. 内容が伝わるコミットメッセージを提示し、利用者の承認を得る。コミットメッセージは `<種別>: 作成者<エージェント名>。<変更内容>` の形式にする。エージェント名は実際に作業しているAI（例: Claude、Codex）の名前にする（例: `fix: 作成者Claude。同じ表示名を持つユーザーAとBがいる場合の表示崩れを修正`）。
4. コミットし、ブランチをpushする。
5. 次の内容を含むDraft PRの草案を作成する。タイトルの先頭には `[作成者<エージェント名>] ` を付ける。

```markdown
## 背景・課題
- issue の背景・課題と同じ内容
## 対応内容
- issue の対応内容と同じ内容
## 確認結果
- 利用者が実際に正常動作を確認できるよう、変更内容に対応した動作確認手順を提示する。
## 補足
- 必要に応じて記載

Closes #Issue番号
```

5. Draft PR作成前に必ず草案を提示し、利用者の承認を得る。
6. PRのURLと、レビュー時に見るべき点を返す。

## 制約

- テスト失敗や未解決の問題を隠さない。
- 認証や権限が不足している場合は停止する。
- PRをReady状態にせず、マージもしない。
