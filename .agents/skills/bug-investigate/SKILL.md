# 不具合を調査する

## 手順

1. 症状と期待する動作を整理する。
2. 関連するコード、テスト、設定、変更履歴を確認する。
3. 可能なら再現し、ログやテストで根拠を集める。
4. 原因と影響範囲を特定する。断定できない点は推測と明記する。
5. 次の形式で簡潔に報告する。

```markdown
## 調査結果
- 判定: 不具合 / 仕様 / 未確定
- 原因:
- 根拠:
- 影響範囲:
- 修正方針:
- リスク:
```

## 制約

- 調査中はコードを変更しない。
- Issue、ブランチ、PRを作成しない。
- 再現できない場合は、不足している情報を示す。
