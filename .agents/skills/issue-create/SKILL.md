# GitHub Issueを作成する

## 手順

1. 依頼された成果、影響範囲、制約、判明している再現条件を整理する。
2. 関連するソースコード、テスト、ドキュメント、最近の変更履歴を確認する。推測をリポジトリ上の事実として扱わないこと。
3. 利用可能なGitHub連携機能、または`gh issue list --state all --search <キーワード>`を使用し、公開中・完了済みのIssueから重複候補を検索する。
4. 重複するIssueが存在する場合は、利用者から新規作成を明示されていない限り、新しいIssueを作成せず、既存IssueのURLと重複する理由を示す。
5. 1つの実行可能な成果を表す、簡潔な日本語タイトルを作成する。
6. 必要な情報がある項目だけを使用して、本文を作成する。

   ```markdown
   ## 背景・課題

   ## 対応内容

   ## 受け入れ条件

   - [ ] 条件を、検証可能な表現で記載する

   ## 補足
   ```

7. 不具合の場合は、判明している再現手順、期待する動作、実際の動作、環境情報を記載する。
8. ラベルや担当者を設定する場合は、リポジトリに存在するものだけを提案する。不確かなメタデータは省略する。
9. 利用者から即時作成を明示されていない限り、公開前に最終的なタイトル、本文、メタデータを提示して確認を得る。
10. 利用可能なGitHub連携機能を使用してIssueを作成する。利用できない場合は、認証状態と対象リポジトリを確認してから`gh issue create`を使用する。
11. 作成したIssueの番号とURLを返す。作成に失敗した場合は、成功したと報告せず、エラー内容を示す。

## 品質ルール

- 1つのIssueでは、独立して完了できる1つの成果だけを扱うこと。
- 受け入れ条件は、観測および検証が可能な表現にすること。
- 対象範囲が明確になる場合は、関連ファイル、ルート、API操作、既存Issueへの参照を記載すること。
- リポジトリ内の根拠がない実装方法を断定しないこと。
- 秘密情報、認証情報、トークン、機密性のある利用者データを含めないこと。
